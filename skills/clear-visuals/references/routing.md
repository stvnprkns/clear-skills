# Routing

## Principle

Route by the reader's dominant cognitive task, not artifact file type or the user's requested label.

## Routing table

| Dominant task | Primary owner | Add another owner when |
| --- | --- | --- |
| perceive trend, magnitude, distribution, association | clear-charts | table lookup or dashboard context is material |
| retrieve exact values/attributes | clear-tables | a pattern overview changes selection |
| trace sequence, dependency, hierarchy, system | clear-diagrams | narrative staging or quantitative flow width is central |
| monitor several views and act | clear-dashboards | individual chart/table defects require domain depth |
| build a mental model over sequence | clear-explainers | charts/diagrams carry core evidence/topology |
| decode specialized quantitative structure | clear-dataviz | standard chart baseline needs comparison |

## Reject when

- a domain is included merely because its artifact appears on the page;
- the umbrella skill restates a domain rule;
- two owners issue contradictory recommendations without a primary-task decision;
- the requested form is accepted before routing the actual question.

## Escape conditions

- Route a simple mixed artifact to one primary owner if secondary elements are incidental.
- Use dashboard as primary for cross-view state even when every component is a chart.
- Use explainer as primary when sequence controls meaning, even if scenes are diagrams.

## Audit signals

- repeated findings across owners;
- chart polish proposed before dashboard hierarchy;
- table converted to chart despite exact lookup;
- diagram chosen for a quantitative magnitude comparison;
- specialized form assessed without a standard baseline.
