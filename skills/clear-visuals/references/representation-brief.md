# Representation Brief

Create this brief before building a cross-domain artifact.

| Field | Required answer |
| --- | --- |
| Reader | role, literacy, frequency, constraints |
| Decision/purpose | action, explanation, monitoring, discovery, documentation |
| Primary question | one sentence |
| Secondary questions | only those required in the same artifact |
| Cognitive tasks | rank, lookup, trace, compare, diagnose, simulate, etc. |
| Evidence | data/source and known uncertainty |
| Constraints | medium, size, interaction, accessibility, brand, technology |
| Candidate forms | at least two plausible forms when ambiguous |
| Choice | primary representation and why |
| Tradeoff | what becomes harder or moves secondary |
| Verification | states and claims that must be tested |

## Reject when

- the brief names a form but no question;
- every secondary question is promoted to primary;
- constraints are invented from implementation preference;
- the chosen form has no stated rejection condition;
- accessibility is deferred without identifying an equivalent path.

## Escape conditions

A familiar, low-risk artifact may need only reader, question, form, and verification. Do not turn the brief into ceremony.
